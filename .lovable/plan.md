
# Farm Naturale — Working Grant Demo Plan

Goal: a live farmer journey a grant reviewer can click through end-to-end, with real signup, persisted data, real AI diagnosis, and simulated money flows. Focused on the **Farmer** role (mobile experience). Admin dashboard stays visual for now.

## What will actually work

Every step below persists to the database, tied to the signed-in farmer.

1. **Sign up / log in** — email + password + Google (Lovable Cloud auth). Auto-create a `profiles` row on signup with name, phone, village, land size.
2. **Onboarding** — farmer picks crops of interest, garden size, goals. Saved to profile.
3. **My Home Garden** — create a garden, add plots, log crops planted, watering, harvest events. Timeline persists.
4. **AI Crop Doctor** — upload a leaf photo, real diagnosis from Gemini vision (Lovable AI Gateway). Result saved to a `diagnoses` table with photo, disease, severity, treatment, follow-up steps. History visible.
5. **Marketplace** — browse a seeded product catalog (seeds, tools, organic inputs). List your own harvest for sale. Place orders. Simulated payment — order status flows Pending → Paid → Shipped → Delivered.
6. **Wallet** — starting demo balance. Debits on marketplace purchases, credits on harvest sales, payout requests logged. Transaction history persists.
7. **Consulting request** — submit a question to an agronomist (mock reply auto-generated by AI after a short delay so the flow completes on-demo).
8. **Certificates** — training completion cert generated when farmer finishes a short in-app learning module.

## Tech setup

- **Lovable Cloud** enabled (auth + Postgres + storage + server functions).
- **Storage buckets**: `crop-photos` (private, farmer-scoped), `product-images` (public, seeded).
- **AI**: `google/gemini-3-flash-preview` vision via Lovable AI Gateway, called from a server function that reads the uploaded photo and returns structured `{ disease, confidence, severity, treatment, prevention }`.
- **RLS**: every table scoped to `auth.uid()`. Admin route stays visual (no admin role wiring yet).
- **Seeded data**: ~20 marketplace products and 3 learning modules seeded via migration so the demo is populated on first login.

## Data model (public schema, RLS on, grants issued)

```text
profiles(id=auth.users, full_name, phone, village, land_size_acres, avatar_url, created_at)
gardens(id, user_id, name, size_sqm, location, created_at)
plots(id, garden_id, crop, planted_on, area_sqm, status)
garden_events(id, plot_id, kind: watered|fertilized|harvested|note, note, occurred_at)
diagnoses(id, user_id, photo_path, crop, disease, confidence, severity, treatment, prevention, created_at)
products(id, seller_id nullable, title, category, price_cents, unit, image_url, stock, description)
orders(id, buyer_id, total_cents, status, created_at)
order_items(id, order_id, product_id, qty, unit_price_cents)
wallet_transactions(id, user_id, kind: credit|debit|payout, amount_cents, reason, ref_id, created_at)
consulting_requests(id, user_id, question, crop, reply, replied_at, created_at)
learning_progress(id, user_id, module_id, completed_at)
certificates(id, user_id, module_id, issued_at, code)
```

Wallet balance is a view/RPC that sums `wallet_transactions`.

## Server functions (TanStack `createServerFn`)

- `getMyProfile`, `updateProfile`, `completeOnboarding`
- `listGardens`, `createGarden`, `addPlot`, `logGardenEvent`
- `diagnoseCropPhoto(photoPath, crop)` → uploads signed URL to Gemini, parses structured output, inserts `diagnoses` row
- `listProducts`, `createListing`, `placeOrder`, `getOrder`
- `getWalletBalance`, `listTransactions`, `requestPayout`
- `submitConsultingRequest` (kicks off an AI-generated reply)
- `completeModule` → issues certificate

## Screen wiring (mobile shell stays as-is visually)

Each existing prototype screen is rewired to real data:
- Login/Signup → real Supabase auth, redirect to onboarding if profile incomplete.
- Dashboard → live counts (gardens, active plots, unread diagnoses, wallet balance).
- Home Garden → live gardens/plots, add-plot sheet, event log.
- Crop Doctor → camera/file picker → upload → server fn → result screen with history.
- Marketplace → seeded catalog + "Sell my harvest" flow.
- Cart/Checkout → simulated payment, order confirmation, wallet debit.
- Wallet → live balance + transaction list + payout request.
- Consulting → submit form + reply thread.
- Certificates → list issued certificates with shareable code.

Admin route (`/admin`) is left as the current visual dashboard; a note says analytics are illustrative for the grant demo (can wire later on request).

## Out of scope for this pass

- Buyer / agronomist / admin roles as separate accounts.
- Real payment rails (Stripe test mode).
- Delivery tracking, SMS notifications, multi-language.

Can be added incrementally after the grant demo.

## Build order

1. Enable Lovable Cloud, add auth (email + Google), profiles + onboarding.
2. Migration for all tables + RLS + grants + seed data + storage buckets.
3. Server functions.
4. Rewire mobile screens to live data, screen by screen in the order above.
5. AI Crop Doctor with real Gemini call last (depends on storage + diagnoses table).
6. Smoke-test the full farmer journey.
